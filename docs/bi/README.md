# SK BI 报表系统设计文档

## 1. 文档用途

本目录是 SK BI 第一版的产品与开发基线，面向产品经理、架构师、前后端开发、测试人员以及后续参与实现的 AI Agent。实现过程中如需改变公共接口、数据表或存储过程契约，应先更新对应文档，再修改代码。

第一版的核心目标是：基于 MySQL 存储过程数据集，提供“上方组件区域＋下方表格区域”的报表、表格异构下钻、动态字段映射、查询控件、Excel 导出和打印能力，并确保配置保存后无需重启即可生效。两个区域可以单独存在，也可以同时存在，彼此数据结构不要求相关。

## 3. 建议实施顺序

```mermaid
flowchart LR
    A[若依基座与元数据库] --> B[数据源与存储过程元数据]
    B --> C[报表配置管理]
    C --> D[运行时查询引擎]
    D --> E[动态表格与异构下钻]
    E --> F[图表/指标卡/仪表盘]
    F --> G[导出/打印/版本回滚]
    G --> H[性能、安全与验收]
```

每个阶段的详细任务和完成定义见 [08-test-and-roadmap.md](08-test-and-roadmap.md)。不得先实现自由画布、移动端、跨数据库或普通 SQL 数据集等第一版明确排除的能力。

## 4. 核心术语

| 术语 | 定义 |
|---|---|
| 报表 | 由 UUID 唯一标识的页面，包含查询控件，以及可选的组件区域和表格区域。 |
| 组件区域 | 报表上方区域，可包含一个或多个柱状图、折线图或指标卡，组件之间数据可完全无关。 |
| 表格区域 | 报表下方全宽区域，最多包含一个主表格，负责动态字段展示和异构下钻。 |
| 组件 | 组件区域内的图表或指标卡，拥有唯一 `componentKey` 并独立取数。 |
| 路由/层级 | 表格区域的一种下钻状态。每个层级可拥有完全不同的字段结构。 |
| 异构下钻 | 表格下钻前后字段数量、字段含义可以完全不同的钻取方式。 |
| 钻取边 | 从一个层级到下一层级的配置，包含触发字段、目标路由和载荷字段。 |
| 载荷字段 | 存储过程返回的隐藏 JSON 字段，点击后作为 `p_drill_value` 传回。 |
| 系统参数 | 由服务端注入的参数，例如 `p_user_id`、`p_region_key`、`p_component_key`。 |
| 控件参数 | 查询控件通过参数映射传给存储过程的值，例如 `p_date_start`。 |
| 配置版本 | 每次保存后的完整只读快照；当前配置立即生效，版本用于审计和回滚。 |

## 5. 第一版技术基线

- 后端：JDK 17、Spring Boot 3、Spring Security、JWT、MyBatis、Redis。
- 前端：Vue 3、TypeScript、Vite、Pinia、Element Plus。
- 可视化：Apache ECharts；表格：VXE-Table；Excel：ExcelJS。
- 数据库：MySQL 8；系统元数据库与业务数据源物理或逻辑分离。
- 基座：RuoYi-Vue Spring Boot 3 分支配合 Vue3 TypeScript 前端，参考[若依官方版本说明](https://doc.ruoyi.vip/ruoyi-vue/)。

依赖的精确版本应在开始编码时统一锁定，不允许各模块自行选择冲突版本。

## 6. 全局约束

- 报表 URL 固定为 `/report/view/{uuid}`，UUID 不能替代权限校验。
- 所有报表必须登录后访问；报表 ACL 同时支持角色和用户。
- 第一版只支持 MySQL 8、IN 参数和单结果集存储过程。
- 配置保存后立即生效，无草稿、发布和审批流程；每次保存自动留存版本。
- 报表数据不进入 Redis；Redis 仅缓存配置和短期控件选项。
- 报表至少启用一个区域；组件区域可包含多个组件，表格区域最多一个表格并固定显示在组件区域下方。
- 组件区域与表格区域分别调用存储过程，结果字段和业务含义可以完全不同；查询控件可选择作用目标。
- 表格全量取数后由前端分页和排序；默认 50,000 行、60 秒，平台硬上限 200,000 行。
- 第一版不支持匿名报表、移动端设计、控件级联、服务端分页排序、多结果集、普通 SQL 数据集和 API 数据源。
