# 测试、验收与实施路线图

## 1. 测试策略

测试分为单元测试、后端集成测试、前端组件测试、端到端测试、性能测试和安全测试。所有公共接口、DDL 和存储过程行为以本目录文档为唯一验收基线。

### 1.1 测试环境

- MySQL 8：一个元数据库、至少两个独立业务数据库。
- Redis：支持缓存和 Pub/Sub，多实例测试至少启动两个 Spring Boot 实例。
- 测试数据：小数据、50,001 行截断数据、200,001 行硬上限数据、特殊字符和复合键。
- 浏览器：项目确定的 Chrome/Edge 当前企业支持版本，桌面分辨率至少覆盖 1280×720 和 1920×1080。

## 2. 单元测试

### 2.1 参数绑定器

- 系统、区域、组件、控件、钻取、常量和 NULL 七种来源正确绑定。
- `p_region_key` 由目标对象配置绑定为 COMPONENT 或 TABLE，客户端不能覆盖。
- 根层正确产生空 `p_drill_field` 和 NULL `p_drill_value`。
- 日期范围拆为两个 DATE，多选序列化为 JSON 数组。
- 数字越界、非法日期、错误 JSON、缺少必填控件在数据库调用前失败。
- 客户端提交 `p_user_id` 无法覆盖安全上下文。
- 参数顺序以数据库 ordinal 为准，不依赖 JSON 数组顺序。

### 2.2 配置校验器

- 报表至少启用一个区域，允许多个 COMPONENT 对象但最多一个 TABLE 对象。
- 每个对象存在唯一 `componentKey` 和 `ROOT`；上方组件只有 ROOT，下方表格可有多个路由。
- 表格路由编码唯一，钻取图无环，目标层级可达；上方组件配置钻取边时校验失败。
- 触发字段、载荷字段、样式字段和图表映射引用真实字段。
- TABLE/BAR/LINE/KPI 的字段类型和配置完整。
- 控件只映射其目标上方组件或下方表格，参数类型兼容。
- 过程签名完整映射，OUT/INOUT 和多结果集配置被拒绝。
- 最大行数、超时、栅格坐标和尺寸符合平台边界。

### 2.3 样式与序列化

- 合法 `#FF0000,bold`、`#333333,normal` 正确解析。
- 大小写十六进制均允许；3 位色值、CSS、HTML、脚本和多余 token 被忽略。
- BigDecimal、超大整数、日期、日期时间、布尔和 MySQL JSON 正确输出。
- Excel 公式前缀字符串被转义，数字和日期单元格仍保持类型。

## 3. 后端集成测试

### 3.1 数据源与元数据

- 新增两个 MySQL 数据源、连接测试、修改凭据和停用生命周期正常。
- 密码数据库值不是明文，API 和日志不包含密码或密文。
- 正确发现参数名称、顺序、模式、类型和签名哈希。
- 改变参数顺序、类型或名称后运行查询返回 `BI_SP_SIGNATURE_CHANGED`。
- 无数据源 ACL 的开发者无法选择、读取过程或测试数据源。

### 3.2 配置事务和缓存

- 创建报表生成 UUID、默认组件、ROOT 和版本 1。
- 完整配置保存要么全部成功，要么全部回滚。
- 两个用户以相同版本并发保存，后提交者收到版本冲突。
- 保存后 Redis 缓存删除并广播；两个应用实例在 2 秒内读取新版本。
- 回滚版本 3 时创建新的当前版本，不删除中间版本。
- 回滚引用已停用数据源或签名失效过程时校验失败。

### 3.3 查询执行

- 同一过程按 `p_region_key` 和 `p_component_key` 返回指标卡、图表和表格完全不同的结构。
- 组件覆盖过程使用自己的数据源、签名和参数映射。
- 根层、门店明细和订单层分别返回不同列并正确映射。
- 缺少可见、载荷或样式字段返回 `BI_RESULT_FIELD_MISSING`。
- 未配置额外列不会出现在 API 响应。
- 第 50,001 行触发 `truncated=true`，响应恰好 50,000 行。
- 超时、连接失败、过程 SIGNAL 和取消请求映射为正确错误码。
- 第二个结果集被检测并拒绝。

### 3.4 权限

- 直接用户 ACL、任一角色 ACL 和管理员绕过行为正确。
- 无 ACL、停用和删除报表对普通用户不泄露存在性。
- 用户 A 无法查询或导出用户 B 的未授权 UUID。
- 每个存储过程分支收到的 `p_user_id` 与当前登录用户一致。
- JWT、数据库主机、SQL、过程异常明文和控件值不进入错误响应。

## 4. 前端测试

### 4.1 设计器

- 栅格新增、拖动、缩放、复制、删除和重载后位置一致。
- 创建多个上方图表/指标卡，并为下方表格创建三层异构路由。
- 删除被引用字段、路由、控件和数据源时出现明确阻止信息。
- 参数同步后新增/删除/变化参数正确高亮。
- 未保存离开提示、保存成功状态和版本冲突恢复正常。
- 版本差异分类可读，回滚二次确认有效。

### 4.2 运行页

- 必填控件无默认值时不自动查询；填写后只刷新目标对象。
- 控件变化后全局查询将受影响表格恢复 ROOT；上方组件按绑定关系刷新，未绑定对象状态保留。
- 上方柱状图、折线图、指标卡和下方表格渲染正确，任一对象失败不影响其他对象或区域。
- 表格列、固定、格式、样式、虚拟滚动和动态字段变化正确。
- 50,000 行排序作用于完整数组后分页，而不是只排序当前页。
- 只有下方表格列点击能够异构下钻，上方柱状图/折线图点击不改变表格状态。
- 下方表格面包屑返回上级后请求与数据正确。
- 旧请求晚于新请求返回时，不覆盖新数据。
- `truncated=true` 的提示在分页、排序和导出期间持续可见。

### 4.3 导出与打印

- 单表导出包含全部已加载行、字段顺序、显示名称和正确数据类型。
- 整报表生成概览及每组件工作表，工作表名合法且唯一。
- 截断时必须确认，工作簿中包含截断说明。
- 公式注入字符不被 Excel 执行。
- 打印包含当前组件状态和当前表格页，隐藏交互按钮，结束后恢复页面。

## 5. 端到端验收场景

### 场景 A：两区域独立取数

1. 管理员创建业务数据源并授权 BI 开发者。
2. 开发者创建报表并选择 `sp_bi_sales`。
3. 在上方组件区域创建销售额指标卡和销售趋势图，在下方表格区域配置销售明细表。
4. 三个取数对象共享日期控件，门店控件只绑定表格；通过 `p_region_key` 和不同 `p_component_key` 返回互不相关的数据结构。
5. 查看者获得角色 ACL 后访问 UUID，上方组件和下方表格均正确加载。

通过标准：未写任何组件专用前端代码，查询日志显示相同过程、正确区域键和不同组件键；任一区域失败不影响另一区域。

### 场景 B：三级异构下钻

1. ROOT 表格显示日期、门店、销售额。
2. 点击门店列，以 JSON 载荷进入字段结构不同的门店明细表格层。
3. 点击客户列，以包含日期、门店和客户的 JSON 进入订单表格层。
4. 通过面包屑返回 ROOT。

通过标准：三层字段数量和含义不同，过程收到不变的 `p_component_key=main_table` 及正确钻取路由和值，上方组件状态不变。

### 场景 C：热生效和回滚

1. 查看者保持运行页打开。
2. 开发者修改销售额显示名称和图表颜色并保存版本 9。
3. 查看者下一次查询收到配置过期提示并加载版本 9。
4. 开发者回滚版本 8，生成版本 10。
5. 查看者再次加载版本 10。

通过标准：整个过程不重启应用，任何新请求在保存后 2 秒内使用新配置。

### 场景 D：权限和安全

1. 用户 A 有报表角色授权，用户 B 无授权。
2. A 查询并验证结果只包含其 `p_user_id` 可见数据。
3. B 直接访问 A 的 UUID，得到不泄露资源存在性的错误。
4. A 修改请求体尝试传入 B 的用户 ID。

通过标准：服务端始终注入 A 的身份，篡改被忽略并进入安全审计。

## 6. 性能验收

数据库过程执行时间单独记录，不计入前端渲染目标，但计入用户端总耗时展示。

| 指标 | 目标 |
|---|---:|
| 配置保存到新请求生效 | ≤ 2 秒 |
| 50,000 行响应接收后的首屏渲染 | ≤ 3 秒 |
| 50,000 行前端单列排序 | ≤ 500 毫秒 |
| 前端分页切换 | ≤ 200 毫秒 |
| SQL 控件 1,000 项渲染 | ≤ 1 秒 |
| 组件查询额外应用开销（不含 DB 和传输） | P95 ≤ 500 毫秒 |
| 普通运行配置缓存命中接口 | P95 ≤ 200 毫秒 |

参考客户端需在测试报告中记录 CPU、内存、浏览器版本和网络条件。性能不达标时优先分析序列化、传输、前端响应式代理和虚拟表格，不得通过删除安全校验规避。

### 6.1 压力场景

- 单用户 10 个组件同时查询，验证前端并发 4 和排队。
- 100 个用户并发访问不同报表，验证全局并发许可和连接池。
- 20 个慢查询占满单数据源并发，验证其他数据源不受影响。
- 多实例同时保存和读取同一报表，验证缓存失效和乐观锁。
- 200,001 行结果验证平台硬上限和应用内存稳定。

## 7. 安全测试

- UUID 枚举、水平越权、角色变更后旧 JWT 权限、导出越权。
- SQL 选项中的多语句、注释、DML、DDL、CALL、锁和 outfile 绕过。
- 存储过程名、组件键、字段名和路由值注入。
- 控件、显示名、tooltip、样式字段和结果值 XSS。
- Excel 公式注入。
- 超大 JSON、深层 JSON、多选超限和压缩炸弹式响应。
- 日志、错误响应、版本快照和 Redis 中的凭据及敏感数据扫描。
- Redis 失效消息伪造风险和重复消息幂等性。

## 8. 实施路线图

### 阶段 1：基座与数据源

- 引入若依 Spring Boot 3 与 Vue3 TypeScript 基座。
- 建立 BI 模块、菜单、权限标识和元数据库迁移。
- 实现数据源加密、ACL、连接池、连接测试和过程参数发现。
- 完成数据源与签名相关集成测试。

完成定义：管理员能安全配置多个 MySQL 数据源；开发者只能读取被授权数据源的受支持过程和参数。

### 阶段 2：配置模型与设计器骨架

- 实现报表、ACL、控件、两区域对象、表格路由、字段、钻取边和参数映射 CRUD。
- 实现完整聚合校验、原子保存、版本快照、差异与回滚。
- 实现设计器导航、上方组件栅格、下方表格区域、字段表和参数映射页面。
- 实现 Redis 配置缓存和多实例失效。

完成定义：能配置并保存一个含上方组件、下方表格、控件和三级异构表格路由的报表，保存/回滚 2 秒内生效。

### 阶段 3：查询引擎与动态表格

- 实现参数上下文、强类型绑定、CallableStatement、超时和行数保护。
- 实现结果字段校验、过滤、序列化、样式协议和运行 API。
- 实现运行页、控件、VXE-Table、客户端分页排序和组件错误隔离。
- 实现下方表格异构下钻与面包屑。

完成定义：端到端完成表格三级异构下钻，权限、截断和错误场景通过。

### 阶段 4：图表、指标卡和仪表盘

- 实现柱状图、折线图、指标卡统一渲染器。
- 实现上方图表字段映射和多组件并发调度；图表点击不触发表格下钻。
- 完成仪表盘预览、局部刷新和运行状态管理。

完成定义：同一过程通过区域键和组件键驱动上方三种展示及下方动态表格，区域数据可以完全无关。

### 阶段 5：导出、打印与上线加固

- 实现单组件和整报表 Excel、公式注入保护和截断提示。
- 实现整页打印 CSS。
- 完成监控指标、审计、并发保护、性能测试、安全测试和运维手册验证。

完成定义：本文件全部端到端、性能和安全验收项通过，具备部署和回滚条件。

## 9. 后续 AI 开发任务拆分规则

后续交给 AI 实施时，每个任务必须：

1. 只覆盖一个阶段内的明确子系统；
2. 开始前读取本目录全部相关契约，不自行改变字段或错误码；
3. 同时提交数据库迁移、后端、前端和测试中该任务涉及的部分；
4. 列出与文档的偏差，不能静默新增协议；
5. 完成后执行受影响单元、集成或端到端测试并记录结果。

建议任务粒度示例：“实现数据源元数据发现和签名哈希”，而不是“实现整个 BI 系统”。

## 10. 第一版完成定义

- 所有 8 份设计文档与实现保持一致。
- DDL 可在全新 MySQL 8 元数据库执行。
- 上方柱状图、折线图、指标卡、下方动态表格、查询控件、三级表格异构下钻、ACL、版本、导出和打印全部可用。
- 不重启热生效、多数据源、结果保护和错误隔离通过验收。
- 不存在明文凭据、越权查询、系统参数覆盖、SQL/HTML/Excel 注入等已知高风险缺陷。
- 性能指标达到第 6 节标准，监控、日志、备份和故障处理均有验证记录。
